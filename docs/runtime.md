# Runtime ownership

`src/main.zig` owns window intent, monitor selection, workspace selection, active configuration, and derived layout goals. `src/layout.zig` owns bounded persistent split trees and per-workspace runtime layout state. `src/command.zig` parses commands with an explicit workspace count. `src/config.zig` owns configuration normalization, validation, and generation-tagged evaluation requests. Layout calculation does not call Accessibility.

`native/platform.m` observes Cocoa and Accessibility, retains AX objects, applies geometry, registers Carbon hotkeys, and draws nonactivating panels. Stable identities come from retained `CFEqual` AX objects scoped to each live PID. Titles are display text only. No private window-ID or Space API is used.

All mutations run on the main thread. AX notifications set a dirty flag. Periodic snapshots coalesce at 150 ms, with a repair scan every two seconds. Stateful commands and workspace focus selection also request fresh observations. Failed per-application scans preserve observations as stale. Missing known windows retain their identity and original geometry until AX confirms destruction or their application exits. Missing records stay stale and ineligible, including minimized windows omitted from enumeration. A window missing from a scan stays for 0.5 seconds as a stale ghost. It is not on screen, not focused, and not parked, and it holds no parking or original-geometry recovery ownership. Its tile stays in the layout tree as an inactive leaf, so the other tiles fill the space as they do after a removal. A new window that is not a replacement is inserted as if the ghost's leaf were already gone. A new window replaces a ghost when both have the same PID, the new window's frame at discovery is within 4 points of the ghost's last observed frame, the new window appeared within 0.5 seconds of the ghost's disappearance in either order, and neither window has another candidate. The replacement takes the ghost's tile, workspace, display, floating state, floating frames, and focus-history position. A ghost that reappears in a scan is a normal window again. A ghost without a replacement is removed after 0.5 seconds. The pairing is a frame heuristic. Two windows of one application that swap places at the same frame within 0.5 seconds can trade tiles. If the new window appears first and the old window stays for more than one scan after the manager moves it, the old window's last observed frame no longer matches and the new window keeps the tile it received at discovery. AX calls have an 80 ms messaging timeout. Many stalled applications can still delay the main loop because the timeout applies per call.

Frames use global top-left points in Zig. The Cocoa adapter converts using the primary display height. Visible monitor frames exclude the menu bar and Dock. Full physical bounds prevent parked windows from crossing another display. CG on-screen bounds match PID, layer, and geometry only to avoid moving windows on another native Space. A match requires exactly one AX candidate and one CG candidate. Ambiguous windows remain unmanaged unless the runtime already owns their parking recovery. The match never assigns identity or proves native Space membership. This safety heuristic can omit unusual windows. Native fullscreen blocks its display conservatively, including when its Space is not current.

Native placement owns `idle`, `animating`, and `rejected` motion state. Floating intent adopts observed geometry only while placement is idle, so intermediate animation frames cannot replace the requested destination. Reconciliation submits goals against live native geometry. Visible goals coalesce within two points. Verified parking and rollback use exact coalescing before their separate readback checks.

AX geometry can update before matching WindowServer bounds. A successful frame write permits visibility convergence retries for 250 ms. A scan retries at most twice, with a 10 ms wait before each retry. Only uniquely matched AX windows without a CG match can request a retry. Minimized and native-fullscreen windows cannot request retries. This budget limits retry eligibility, not total synchronous scan duration. Animation evaluation samples its clock after observation and configuration work, so newly created animations do not receive negative progress.

Binding names refer to physical keys, not characters produced by the active input layout. Letter, digit, and punctuation names use the ANSI positions from the macOS SDK `Events.h` virtual-key constants. `section` names the ISO key at code `0x0a`. For example, `j`, `k`, and `l` use codes `0x26`, `0x28`, and `0x25`. Numbered workspaces use the physical number row, not the keypad.

## Hotkey delivery watch

macOS can stop delivering Carbon hotkeys without reporting an error. A listen-only session event tap in `native/observe.m` sees each key press that matches a registered binding and records it with the command bound at that moment. `src/delivery.zig` pairs that press with the Carbon delivery, which can arrive up to 250 ms before the press or at any time after it. A press that Carbon has not delivered after 750 ms runs from the recorded command, and every hotkey registers again at most once per five seconds. A Carbon delivery of the same hotkey within one second of that recovery does not run the command a second time. Each recovery is reported on stderr.

The tap needs Input Monitoring permission. The manager never requests it. Without it, the tap does not start and hotkeys work as before without recovery. The tap starts at launch, so permission granted later takes effect at the next start. A listen-only tap never delays a key press, even while the main thread waits on Accessibility. `status.hotkeys` reports `watchdog` as `active` or `unavailable`, with `missed` and `rebinds` counts. `doctor` reports `input_monitoring`.

## Trackpad swipes

With `swipe.enabled`, the same listen-only tap also receives trackpad gesture events and reports the count and mean normalized position of the touching fingers. `src/swipe.zig` starts a gesture when exactly the configured number of fingers touch. It emits one step when the horizontal travel reaches 0.15 and is at least twice the vertical travel. A change in finger count cancels the gesture. The recognizer arms again after every finger lifts, or after half a second without a gesture event. A step selects the display under the pointer and runs `workspace occupied+1` for a left swipe or `workspace occupied-1` for a right swipe through the hotkey path, so rapid swipes coalesce like rapid shortcuts. A step does nothing while a mouse button is held, while the manager is suspended, or during a workspace transition. The tap listens for gesture events only while swipes are enabled, and a reload changes that.

## Placement journal

The manager appends a line to `~/Library/Application Support/HuenWM/journal.jsonl` at each moment where its model and the screen disagreed. Each line is one JSON object with `at` in Unix seconds and an `event`:

- `placement` records a rejected placement, once until the window's error changes. It has the window identity, `pid`, `bundle`, `message`, `workspace`, `display`, the layout `goal`, the `target` frame the manager asks for after the failure, and the `actual` frame, or `null` when the frame is unreadable.
- `transition` records a new `status.transition_error` that is not a placement failure. A repeat of the last recorded message is not recorded again.
- `error` records a hotkey that macOS did not deliver, a failed hotkey registration, or windows left unrestored at shutdown.
- `mark` records a `wrong` command.

The journal never records a window title or a file path. It is not written while `--app` limits the manager to one application. The file is private to the user, mode 0600, and the manager refuses a symbolic link in its place. Past 1 MiB, the manager renames it to `journal.1.jsonl` and starts a new file, so the two files hold at most about 2 MiB. A failed append is reported on stderr once, and later failures are silent.

Run `huen-wm wrong` right after the manager does something wrong, with an optional note such as `huen-wm wrong did not switch`. The command appends a `mark` with the note, `window_count`, `parked_count`, the workspace shown on each display, and `transition_error`. Notes longer than 200 bytes are cut at a character boundary. The command works while the manager is suspended. `doctor` reports the journal `path`, a count for each event, and `last_mark`. It skips malformed lines.

## Menu-bar presentation

Zig derives a bounded status presentation from committed configuration and the active monitor. The bridge copies terminated UTF-8 strings and at most twelve rows synchronously on the main thread. `NULL` removes the item. AppKit renders the supplied title, tooltip, checkmarks, availability, and commands without querying workspace JSON. There is no workspace popup.

Publication follows successful startup hotkey activation, observation, commands, successful reload, and generation-checked scene completion. Equal presentations do not call AppKit. A monitor identity change invalidates the menu even when its text is unchanged. Menu replacement cancels tracking and detaches old targets. Dispatch rejects stale items, copies the command before calling Zig, and parses the response before another command can replace it. Shutdown removes the item before worker draining and rejects later presentation calls. Validation does not activate a status item.

## Transactions

Startup and validation wait for one isolated evaluation before the application loop starts. Startup installs bindings from that candidate without evaluating Lua again. The executable handles `--config-worker` before Cocoa or window-manager setup. `native/config_worker.c` uses `posix_spawn` with the same executable, a private response descriptor, nonblocking pipes, and a monotonic deadline. It bounds responses, drains error output, and accepts only a complete validated JSON response with a successful exit status. Lua never runs in the live manager. Metatables on consumed tables, sparse arrays, extra collection keys, and NUL field names are rejected.

Reload starts one supervision thread and immediately returns an accepted request ID. The thread owns child termination and reaping on failure, timeout, or cancellation. The application loop polls completed requests without waiting for evaluation. A generation check rejects late completions. Active workspace transitions leave pending completions in the mailbox until settlement. Suspension prevents publication. Carbon registrations reuse stable slots and stage new keys before releasing old ones. A collision rolls back only new registrations. After successful registration, the candidate becomes active in `main` mode. Workspace names remap existing assignments and layout intent. Unmatched assignments are clamped when workspace count shrinks. New-window rules apply at discovery. Restore invalidates pending work. Shutdown drains cancelled requests across application-loop ticks until the supervisor has reaped its child.

`native/scene.m` owns display snapshots and Core Animation covers. It does not move windows. A workspace command records a generation and asks for capture. Its callback performs a bounded AX placement transaction, reads back geometry, rolls back on rejection, commits focus, and fades the matching generation. Missing capture permission takes the same placement path without a cover. Commands that mutate layout wait until the current transition ends. Status remains available. Restore and shutdown cancel capture before restoring geometry.

`status.snapshot_presentation` reports `idle`, `pending`, `instant`, `captured`, or `fallback` with `snapshot_generation`. A matching native capture callback supplies the captured or fallback outcome. Cancelled callbacks cannot update a newer generation.

Visibility changes share a synchronous placement transaction, including reconciliation after rules, reload, workspace-count reduction, and display migration. A transaction first places the windows that end visible, then parks the others from the back of the window stack to the front, so a workspace switch does not show the desktop between them. The stack position comes from the on-screen window list. Windows without one are parked first. Rollback undoes the attempted windows in the reverse order of the attempt. Ordinary placement and rollback verify all four coordinates within two points. Parking preserves size and verifies a one-point vertical strip at a bottom corner, with two-point readback tolerance. macOS can clamp the vertical position to keep the title bar reachable. The accepted strip must meet the source display's bottom edge and avoid every other display's full physical bounds. Reconciliation uses the same predicate to avoid repeated writes. Rejection triggers a verified rollback. Failed rollback retains parking recovery ownership so a parked window remains eligible for repair. Floating intent and pre-parking geometry are separate fields.

Parking tries the right corner, then the left if the first write fails and rollback succeeds. A failed rollback stops further attempts. An already valid left strip remains parked there.

Some applications move a parked window back on screen. A parked window escapes when no corner accepts its frame, the frame overlaps the display's visible frame by more than three points in both directions, and the display layout has not changed in the last two seconds. Every park is verified by readback, so an escape right after a park counts. The first escape parks the window again. An escape within 300 seconds of the previous one stops parking for that window until it closes. An exempt window keeps its workspace and tiles when that workspace shows. While the workspace is hidden, the window stays where its application puts it. `windows[].parking_exempt` reports the exemption, and stderr reports it once with the window identity.

Placement rejection is observable through `status.transition_error`, `windows[].placement_error`, and stderr with a window identity. A failed workspace command attempts rollback without claiming that rollback succeeded. A queued scene command returns `accepted` and a generation, not a claim that placement has completed. The scene has a three-second watchdog, but it cannot execute while synchronous AX work blocks the main thread.

Derived tiles stay inside the display's usable area. Tiles smaller than 80 points in either dimension degrade to floating windows. This threshold is a crowding limit. Application minimum sizes are learned separately, from rejected placements. Normal animation completion verifies geometry. An application that answers a tile with a larger width or height teaches that size as the window's minimum, and the goals are derived again in the same pass. A rejected or app-clamped goal that teaches no larger minimum degrades to floating geometry instead of restarting the same animation indefinitely. A rejected tiled unpark falls back to bounded pre-parking geometry on retry. Application constraints can still reject floating recovery geometry. Such windows retain recovery ownership and an error until placement succeeds.

## Safety and recovery

The process uses a per-user lock and mode-0600 Unix socket. Clients reject sockets owned by another user. The filter `--app dev.huen-wm.fixture` limits discovery before any AX window is retained or changed. Permission checks never prompt.

Original geometry is retained before the first placement. Restore cancels animations for every retained window before any restoration. It reads current minimized and fullscreen attributes rather than trusting the last snapshot. Missing state attributes prevent a write. Only a verified return to original geometry clears restoration eligibility. Explicit restore suspends policy so reconciliation does not tile windows again. Its error response includes an `outstanding` count when restoration remains incomplete. Later restore commands and shutdown retry outstanding windows. Shutdown logs failures and keeps the parking journal for the next start. Recovery never unhides an application or deminimizes a user window.

Persisting titles or guessing a new AX identity would risk moving the wrong window, so recovery after a crash matches only windows of applications that are still running. A parking journal records each window that the process owns at a corner: the application's bundle identifier, process identifier, and launch date, the pre-parking frame, and both corner frames. The process writes the journal before the first parking write of a window and after each reconciliation, and skips a write whose content is unchanged. The write is not synchronized to disk, because a record of an application that ended with the machine cannot match. On the first tick that has displays, the next process pairs each observed window with at most one record of the same application process whose corner has the window's size and left edge within two points. It moves the window to the recorded frame, bounded to the visible frame of the display that the frame overlaps most, and makes that frame the original geometry that restore writes back. A recovered window remains owned when it does not reach that frame or shares it with another window of its application. Recovery returns frames, not workspace membership, layout, or floating state. A restore that leaves no outstanding window, including the one at shutdown, empties the journal. An incomplete restore keeps it, so the next start recovers the windows that restore could not move. `status.parking_recovery` reports the number of records and the recovered and failed windows, or null before the first tick that has displays.

The full native fixture flow passed on one display with instant switching and with scenes enabled. Final checks also cover split resizing, managed fullscreen, binding modes, application commands, and recovery after a fixture's timed minimization. See [feature-completion evidence](verification-feature-completion.md). Two-display tiling passed earlier, but final corner parking has not been exercised on two displays. Remaining checks include broader application constraints, physical hotkeys, native Space changes, monitor removal, scene appearance, borders, and conditional close concurrent with minimization. Full-display capture can be denied independently of Accessibility. Neither permission is necessary for headless config validation.
