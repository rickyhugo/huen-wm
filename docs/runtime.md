# Runtime ownership

`src/main.zig` owns window intent, monitor selection, workspace selection, active configuration, and derived layout goals. `src/layout.zig` owns bounded persistent split trees and per-workspace runtime layout state. `src/command.zig` parses commands with an explicit workspace count. `src/config.zig` owns configuration normalization, validation, and generation-tagged evaluation requests. Layout calculation does not call Accessibility.

`native/platform.m` observes Cocoa and Accessibility, retains AX objects, applies geometry, registers Carbon hotkeys, and draws nonactivating panels. Stable identities come from retained `CFEqual` AX objects scoped to each live PID. Titles are display text only. No private window-ID or Space API is used.

All mutations run on the main thread. AX notifications set a dirty flag. Periodic snapshots coalesce at 150 ms, with a repair scan every two seconds. Stateful commands and workspace focus selection also request fresh observations. Failed per-application scans preserve observations as stale. Missing known windows retain their identity and original geometry until AX confirms destruction or their application exits. Missing records stay stale and ineligible, including minimized windows omitted from enumeration. AX calls have an 80 ms messaging timeout. Many stalled applications can still delay the main loop because the timeout applies per call.

Frames use global top-left points in Zig. The Cocoa adapter converts using the primary display height. Visible monitor frames exclude the menu bar and Dock. Full physical bounds prevent parked windows from crossing another display. CG on-screen bounds match PID, layer, and geometry only to avoid moving windows on another native Space. A match requires exactly one AX candidate and one CG candidate. Ambiguous windows remain unmanaged unless the runtime already owns their parking recovery. The match never assigns identity or proves native Space membership. This safety heuristic can omit unusual windows. Native fullscreen blocks its display conservatively, including when its Space is not current.

Native placement owns `idle`, `animating`, and `rejected` motion state. Floating intent adopts observed geometry only while placement is idle, so intermediate animation frames cannot replace the requested destination. Reconciliation submits goals against live native geometry. Visible goals coalesce within two points. Verified parking and rollback use exact coalescing before their separate readback checks.

AX geometry can update before matching WindowServer bounds. A successful frame write permits visibility convergence retries for 250 ms. A scan retries at most twice, with a 10 ms wait before each retry. Only uniquely matched AX windows without a CG match can request a retry. Minimized and native-fullscreen windows cannot request retries. This budget limits retry eligibility, not total synchronous scan duration. Animation evaluation samples its clock after observation and configuration work, so newly created animations do not receive negative progress.

Binding names refer to physical keys, not characters produced by the active input layout. Letter, digit, and punctuation names use the ANSI positions from the macOS SDK `Events.h` virtual-key constants. `section` names the ISO key at code `0x0a`. For example, `j`, `k`, and `l` use codes `0x26`, `0x28`, and `0x25`. Numbered workspaces use the physical number row, not the keypad.

## Menu-bar presentation

Zig derives a bounded status presentation from committed configuration and the active monitor. The bridge copies terminated UTF-8 strings and at most twelve rows synchronously on the main thread. `NULL` removes the item. AppKit renders the supplied title, tooltip, checkmarks, availability, and commands without querying workspace JSON. There is no workspace popup.

Publication follows successful startup hotkey activation, observation, commands, successful reload, and generation-checked scene completion. Equal presentations do not call AppKit. A monitor identity change invalidates the menu even when its text is unchanged. Menu replacement cancels tracking and detaches old targets. Dispatch rejects stale items, copies the command before calling Zig, and parses the response before another command can replace it. Shutdown removes the item before worker draining and rejects later presentation calls. Validation does not activate a status item.

## Transactions

Startup and validation wait for one isolated evaluation before the application loop starts. Startup installs bindings from that candidate without evaluating Lua again. The executable handles `--config-worker` before Cocoa or window-manager setup. `native/config_worker.c` uses `posix_spawn` with the same executable, a private response descriptor, nonblocking pipes, and a monotonic deadline. It bounds responses, drains error output, and accepts only a complete validated JSON response with a successful exit status. Lua never runs in the live manager. Metatables on consumed tables, sparse arrays, extra collection keys, and NUL field names are rejected.

Reload starts one supervision thread and immediately returns an accepted request ID. The thread owns child termination and reaping on failure, timeout, or cancellation. The application loop polls completed requests without waiting for evaluation. A generation check rejects late completions. Active workspace transitions leave pending completions in the mailbox until settlement. Suspension prevents publication. Carbon registrations reuse stable slots and stage new keys before releasing old ones. A collision rolls back only new registrations. After successful registration, the candidate becomes active in `main` mode. Workspace names remap existing assignments and layout intent. Unmatched assignments are clamped when workspace count shrinks. New-window rules apply at discovery. Restore invalidates pending work. Shutdown drains cancelled requests across application-loop ticks until the supervisor has reaped its child.

`native/scene.m` owns display snapshots and Core Animation covers. It does not move windows. A workspace command records a generation and asks for capture. Its callback performs a bounded AX placement transaction, reads back geometry, rolls back on rejection, commits focus, and fades the matching generation. Missing capture permission takes the same placement path without a cover. Commands that mutate layout wait until the current transition ends. Status remains available. Restore and shutdown cancel capture before restoring geometry.

`status.snapshot_presentation` reports `idle`, `pending`, `instant`, `captured`, or `fallback` with `snapshot_generation`. A matching native capture callback supplies the captured or fallback outcome. Cancelled callbacks cannot update a newer generation.

Visibility changes share a synchronous placement transaction, including reconciliation after rules, reload, workspace-count reduction, and display migration. Ordinary placement and rollback verify all four coordinates within two points. Parking preserves size and verifies a one-point vertical strip at a bottom corner, with two-point readback tolerance. macOS can clamp the vertical position to keep the title bar reachable. The accepted strip must meet the source display's bottom edge and avoid every other display's full physical bounds. Reconciliation uses the same predicate to avoid repeated writes. Rejection triggers a verified rollback. Failed rollback retains parking recovery ownership so a parked window remains eligible for repair. Floating intent and pre-parking geometry are separate fields.

Parking tries the right corner, then the left if the first write fails and rollback succeeds. A failed rollback stops further attempts. An already valid left strip remains parked there.

Placement rejection is observable through `status.transition_error`, `windows[].placement_error`, and stderr with a window identity. A failed workspace command attempts rollback without claiming that rollback succeeded. A queued scene command returns `accepted` and a generation, not a claim that placement has completed. The scene has a three-second watchdog, but it cannot execute while synchronous AX work blocks the main thread.

Derived tiles stay inside the display's usable area. Tiles smaller than 80 points in either dimension degrade to floating windows. This threshold is a crowding limit, not an application minimum-size estimate. Normal animation completion verifies geometry. A rejected or app-clamped goal degrades to floating geometry instead of restarting the same animation indefinitely. A rejected tiled unpark falls back to bounded pre-parking geometry on retry. Application constraints can still reject floating recovery geometry. Such windows retain recovery ownership and an error until placement succeeds.

## Safety and recovery

The process uses a per-user lock and mode-0600 Unix socket. Clients reject sockets owned by another user. The filter `--app dev.huen-wm.fixture` limits discovery before any AX window is retained or changed. Permission checks never prompt.

Original geometry is retained before the first placement. Restore cancels animations for every retained window before any restoration. It reads current minimized and fullscreen attributes rather than trusting the last snapshot. Missing state attributes prevent a write. Only a verified return to original geometry clears restoration eligibility. Explicit restore suspends policy so reconciliation does not tile windows again. Its error response includes an `outstanding` count when restoration remains incomplete. Later restore commands and shutdown retry outstanding windows. Shutdown logs failures but cannot provide recovery after process exit. Recovery never unhides an application or deminimizes a user window. Hard-kill recovery is unsupported. Persisting titles or guessing a new AX identity would risk moving the wrong window.

The full native fixture flow passed on one display with instant switching and with scenes enabled. Final checks also cover split resizing, managed fullscreen, binding modes, application commands, and recovery after a fixture's timed minimization. See [feature-completion evidence](verification-feature-completion.md). Two-display tiling passed earlier, but final corner parking has not been exercised on two displays. Remaining checks include broader application constraints, physical hotkeys, native Space changes, monitor removal, scene appearance, borders, and conditional close concurrent with minimization. Full-display capture can be denied independently of Accessibility. Neither permission is necessary for headless config validation.
